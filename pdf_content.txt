1. Executive Summary 
This document provides the complete development plan for migrating the OFSD fund valuation system 
from a percentage-based compounding model to a share-based (NAV per share) valuation model. This 
migration aligns the system with AXYS (Mauritius) methodology. 
1.1 The Problem 
The current system calculates investor returns by applying a percentage performance rate over a period 
and distributing gains proportionally by capital weight. AXYS operates on a unitised (share-based) model 
where each investor owns shares purchased at the NAV per share on their deployment date, and their 
position value is simply shares multiplied by the current NAV per share. 
When clients join mid-period, the two models diverge: percentage proration gives different results than 
share-based compounding. The share-based model is the contractually correct one. 
1.2 The Solution 
Replace the valuation engine entirely. Every investor position becomes: shares (bought at deployment 
NAV) multiplied by current NAV per share. Performance is derived from NAV movement, not input as a 
percentage. Reconciliation checks total system NAV against AXYS figures.

2. Data Model (New Schema) 
The new schema introduces share classes, NAV tracking, and individual share ownership. All new tables 
are additive; existing tables are modified but not dropped. 
2.1 New Tables 
2.1.1 share_classes 
Each fund has one or more share classes. Each class has exactly one currency. 
Column Type Constraints Description 
id Integer PK, auto  
core_fund_id Integer FK core_funds.id, NOT NULL Parent fund 
class_name String(100) NOT NULL e.g. 'Class I Participating Shares' 
class_code String(20) NOT NULL, UNIQUE e.g. 'KES_I', 'USD_I', 'USD_R' 
currency String(3) NOT NULL, CHECK IN 
('KES','USD') 
Single currency per class 
is_active Boolean DEFAULT true  
created_at DateTime(tz) NOT NULL  
2.1.2 nav_history 
Stores NAV per share for each class at each valuation date. This is the core pricing table. 
Column Type Constraints Description 
id Integer PK, auto  
share_class_id Integer FK share_classes.id, NOT NULL Which class 
nav_date Date NOT NULL Valuation/deployment date 
nav_per_share Numeric(20,6) NOT NULL Price per share on this date 
total_fund_nav Numeric(20,2) NULLABLE AXYS total (for recon) 
source String(20) NOT NULL deployment or valuation 
created_at DateTime(tz) NOT NULL  
UNIQUE CONSTRAINT 
nav_history has a unique constraint on (share_class_id, nav_date, source) to prevent duplicate entries for the 
same class on the same date from the same source type.

3.3 Batch Operations 
POST /api/v1/batches/:batch_id/close 
Close batch and generate export Excel. Triggered automatically at Thursday 9 AM or manually. 
Response: { "status": 200, "data": { "batch_id": 7, "is_open": false, 
"exported_at": "...", 
  "export_url": "/api/v1/batches/7/export", "investors_count": 5, 
"total_deposited": 5000000 } } 
GET /api/v1/batches/:batch_id/export 
Download the batch Excel for Mauritius. Named: {fund}_{class}_{date}.xlsx 
PATCH /api/v1/batches/:batch_id/transfer 
Mark batch as transferred. Triggers investor email (stage 2 of 3). 
Request: { "transfer_transaction_cost": 150.00 } 
PATCH /api/v1/batches/:batch_id/deploy 
Deploy batch. This is the most critical endpoint. Calculates shares for every investor. 
Request: { 
  "deployment_date": "2026-04-01", 
  "nav_per_share": 1329.4779, 
  "total_nav": 1072636.69, 
  "total_shares": 771.92, 
  "transfer_cost": 150.00, 
  "entry_fee_percent": 2.0 
} 
 
Backend calculation per investor: 
net_amount = deposit_amount - transfer_cost_share - (deposit_amount * 
entry_fee_percent / 100) 
investor_shares = net_amount / nav_per_share 
 
Validation check: 
sum(all investor_shares in batch) should approximately equal total_shares 
sum(all investor_shares) * nav_per_share should approximately equal total_nav 
 
Response: { "status": 200, "data": { 
  "batch_id": 7, "deployment_date": "2026-04-01", "nav_per_share": 1329.4779, 
  "total_shares": 771.92, "total_nav": 1072636.69, 
  "investors": [

      "shares": 729.86, "deployment_nav": 1329.4779 }, 
    ... 
  ], 
  "reconciliation": { "calculated_total_shares": 771.92, "diff": 0.00, "status": 
"PASS" } 
} }

3.4 Valuation 
POST /api/v1/valuation/nav 
Monthly valuation. Input current NAV per share and total fund NAV for each class. 
Request: { 
  "valuation_date": "2026-04-10", 
  "classes": [ 
    { "share_class_id": 1, "nav_per_share": 1389.5737, "total_fund_nav": 1072636.69 
}, 
    { "share_class_id": 2, "nav_per_share": 15.1905, "total_fund_nav": 219074.79 }, 
    { "share_class_id": 3, "nav_per_share": 12.9358, "total_fund_nav": 1038.81 } 
  ] 
} 
 
Backend process (per class): 
1. Load all active investor_shares for this class 
2. Calculate system_total_nav = sum(shares_owned) * nav_per_share 
3. Compare system_total_nav to total_fund_nav from AXYS 
4. If difference > tolerance (e.g. 1.00 in currency): return error, do not proceed 
5. If passes: for each investor, calculate market_value = shares_owned * nav_per_share 
6. Calculate performance_pct = (nav_per_share - deployment_nav) / deployment_nav 
7. Save valuation_snapshot for each investor 
8. Save nav_history record for this class + date 
 
Response: { "status": 200, "data": { 
  "valuation_date": "2026-04-10", 
  "classes": [{ 
    "class_code": "KES_I", "nav_per_share": 1389.5737, 
    "system_total_nav": 1072636.96, "head_office_nav": 1072636.69, 
    "difference": 0.27, "status": "PASS", 
    "investors": [{ "client_code": "INV-001", "shares": 729.86, 
      "market_value": 1014178.42, "performance_pct": 4.52 }, ...] 
  }] 
} }

1. User selects valuation date 
2. System loads all active share classes that have deployed batches 
3. For each class, user inputs: Current NAV per Share, Total Fund NAV (from AXYS)

5. Compares calculated total to input total fund NAV 
6. Shows reconciliation status per class (PASS/FAIL with difference) 
7. Preview shows every investor: name, shares, new market value, performance % 
8. User confirms. System saves valuation snapshots.

5.4 Withdrawal Processing 
Withdrawals redeem shares at the current NAV. The process has its own tracker: 
1. Request Received: Record withdrawal request, calculate estimated shares to redeem 
2. Initiated: Sent to Mauritius for processing 
3. Confirmation: Mauritius provides redemption NAV and shares redeemed 
4. Transfer: Funds being sent back to Kenya 
5. Completed: Funds credited, investor shares updated, statement generated 
 
Exit fee rule: If the investor joined the fund less than 6 months ago (from deployment_date to 
withdrawal_date), a 2% exit fee is charged on the withdrawal amount.

7. Entity Relationship Summary 
This section maps how all entities relate to each other in the new system. 
CoreFund (1) ---> (many) ShareClass 
ShareClass (1) ---> (many) Batch       [each batch belongs to exactly one class] 
ShareClass (1) ---> (many) NavHistory   [NAV tracked per class per date] 
Batch (1) -------> (many) Investment    [investors in the batch] 
Investment (1) --> (many) InvestorShares [shares per class per batch] 
InvestorShares (1) -> (many) ValuationSnapshot [monthly valuations] 
 
Key constraints: 
• A ShareClass has exactly ONE currency (KES or USD). This is enforced at database level. 
• A Batch belongs to exactly ONE ShareClass. Two investors in different classes cannot share a 
batch. 
• An investor can have multiple InvestorShares records (different classes, different batches, 
different deposits). 
• NavHistory has one record per class per date per source. No duplicates. 
• ValuationSnapshot has one record per InvestorShares per valuation date.

8. Glossary 
Term Definition 
NAV Net Asset Value. The total value of all assets in a fund or class. 
NAV per Share The price of one share in a class. Market value = shares x NAV per share. 
Share Class A subdivision of a fund with its own NAV and currency. E.g. KES Class I, USD Class 
I, USD Class R. 
Deployment When investor funds are actually invested by AXYS. This is when shares are 
purchased. 
Deployment NAV The NAV per share on the date of deployment. Used to calculate initial shares. 
Reconciliation Checking that system-calculated totals match AXYS figures. 
Batch A weekly grouping of investors (Friday to Thursday) sent to AXYS together. 
Contract Note Official document from AXYS confirming deployment details. 
Entry Fee 2% fee charged on deposit amount before shares are purchased. 
Exit Fee 2% fee charged on withdrawal if investor exits within 6 months of joining. 
Transfer Cost Bank transfer fees for moving money to Mauritius. 
AXYS The offshore fund manager in Mauritius that manages the actual fund.
